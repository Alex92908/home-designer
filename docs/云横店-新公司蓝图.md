# 云横店 v2 —— 浏览器里的 AI 电影片场

> 蓝图 v2（2026-07-08 重写）。独立于筑雅 zhuyahome 的第二条产品线，
> 共用技术底盘，品牌/域名/用户完全分开。本分支（studio-mvp）孵化。
> v1 的增量补丁已合并进本版，本文档为唯一权威版本。

## 一、一句话定位

**AI 视频时代的「横店」：在浏览器里选景、排分镜、摆走位、K 机位，
一键导出喂给 AI 视频模型的全套控制素材。**

卖的不是 3D 模型，是「**导演控制权**」：场景一致性、机位精确性、走位
时机——这三样是纯文生视频的死穴，也是白模 previz 工作流的全部价值。

## 二、为什么是现在（已获三重外部验证）

1. **Seedance 2.5（2026-06-23）把「3D 白模 previz」做成官方原生输入**：
   喂白模视频 + 风格参考，模型复刻相机轨迹渲染成片。需求被头部模型
   官方造好了，但**入口门槛是 Blender/UE5**——我们把它降到浏览器零安装。
2. **开源侧同构成立**：Wan VACE 支持 depth/pose 控制 V2V。闭源与开源
   两条下游的**通用货币都是深度序列**——我们导出的控制包两头通吃。
3. **PrevizWhiz（CHI 2026）**：学术界已把「粗糙 3D + ComfyUI」做成系统。
   验证 + 警钟：这个空间即将拥挤，差异化必须钉死在
   **浏览器零安装 + 现成场景库 + 服务不会 3D 的大众创作者**。

## 三、核心对象模型（产品骨架）

```
Project 片子
 └─ Scene 片场          （一个 3D 场景：自建/模板/未来 3DGS 导入）
     ├─ Actor[] 角色     （占位人形/物件 + 路径 + 动作片段，二期）
     └─ Shot[] 镜头      （原子单位）
         ├─ camera      机位路径（预设 → 未来关键帧自定义）
         ├─ duration    时长（对齐视频模型 5s/10s 档）
         ├─ prompt      本镜提示词（风格/内容描述，随控制包导出）
         └─ takes       产物（参考视频/首尾帧/深度序列）
 └─ ControlPack 控制包   （整个分镜批量导出：N 组产物 + storyboard.json）
```

**分工红线**：我们锁「空间 + 构图 + 机位 + 走位时机」（blocking），
表演细节、材质光影升华是下游 AI 视频模型的活。守住红线，
产品不会滑向无底洞（角色绑定/物理/渲染农场都不做）。

## 四、用户旅程

1. **选景**：从场景库挑片场（起步 = 筑雅别墅/庭院 + CC0 搭的通用片场）
   或用筑雅设计器自建。
2. **排分镜**：加镜头 → 每镜选机位预设、调时长、写提示词 → 拖排顺序。
3. **摆走位**（二期）：拖角色占位进场景，画路径、选动作、对时间轴。
4. **导出**：一键批量拍摄 → 控制包（每镜参考视频 + 首尾帧 + 可选白模/
   深度序列 + storyboard.json 机位元数据）。
5. **成片**：A) 控制包下载 → 用户自己的 ComfyUI/VACE（零 API 成本，
   服务本地算力玩家）；B) BYOK 站内直喂即梦/Kling/Seedance → 回填成片。

## 五、客户（按优先级）

1. **AI 短片/短剧创作者**（即梦/Kling/Seedance/本地 ComfyUI 用户）——
   最痛：多镜头同场景不一致、机位失控。量大，短剧市场已验证付费。
2. **电商/本地商家广告**——产品放进"别墅/咖啡馆"拍 15 秒。
3. **独立影视 previz**——浏览器零门槛替代 Blender 白模。
4. （远期）**景区/文旅数字分身**——B 端代扫代运营 + 授权分成。

## 六、路线图（里程碑制）

### M0 单镜头录制 ✅（已完成）
外观图 🎬「出短片」：三机位预设（环绕/推近/摇臂）→ 参考视频 + 首尾帧。

### M1 分镜工作台 ◀ 当前
镜头列表（预设/时长/提示词）、排序、批量拍摄、storyboard.json 元数据。
分镜是产品的原子结构——没有它，M0 只是玩具。

### M2 控制包完整化
- 导出风格选项：**实景（默认，本身就是最强参考视频）** / 白模灰盒
  （overrideMaterial，Seedance previz 规格）/ 深度序列（VACE/ControlNet）
- 打包下载 + Dogfood：喂本地 ComfyUI + Wan VACE 验证白模→成片链路

### M3 走位动画
- 物件路径动画（车开进/门开）——three.js 关键帧，易
- 角色占位（Mixamo 人形 + 路径 + 动作片段 + 每镜时间轴）——
  打斗/生活感镜头的前提；方块人级别即可，AI 上色时替换成真人

### M4 站内成片
BYOK 视频模型代理（即梦优先；Seedance 2.5 白模 API 公开即接入），
首尾帧/参考视频模式，任务轮询 + 成片回填到 Shot.takes。

### M5 独立产品化
- 独立域名/品牌/首页，通用片场库（咖啡馆/巷子/办公室…）
- 3DGS 导入（.splat/.spz 当环境，Three.js 生态已成熟）
- 创作者市集（上传场景收租分成——网络效应所在）
- （远期）AI 文生动作、景区授权、UE/USD 导出

## 七、护城河 / 风险

- **护城河**：分镜级工作流（非单点功能）+ 场景库内容 + 市集网络效应 +
  控制包"两头通吃"（云端模型 & 本地开源）。
- **最大风险**：视频模型厂商原生做出完整 3D 编排。对策：做工作流和
  内容库不做模型——模型越强，场景库和分镜工具越值钱，水涨船高。
- **版权红线**：MVP 只用自建/CC0；真实景区推迟到有用户筹码时再谈。
