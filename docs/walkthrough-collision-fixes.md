## 1. 室内墙壁可以被穿过

**现象**：用屏幕摇杆或 WASD 顶着室内墙走，会直接穿过去。

**根因**：旧碰撞用「点属于哪个房间矩形」的成员判定（`curRoom===newRoom → 放行`）。但房间碰撞矩形会**互相重叠**（例如走廊 Z[-1.84,0.44] 与客厅 Z[0.16,5.04] 重叠 0.28m）。在重叠区里，移动前后两点会被误判为「同一个房间」，于是判定放行，人就滑了过去。

**修复**（`HouseCanvas.tsx` `blocksMovement`）：改为**墙线穿越**模型，直接复刻渲染器 `wallSegments` 的实心墙位置——
- `crossesH(zf, xlo, xhi)`：移动线段是否跨过一条水平墙线；`crossesV` 对称处理竖直墙。
- 遍历当前楼层的房间矩形，对每条**未被隐藏**（`!r.hides?.X`）的边做穿越检测；走廊只检测短边（长边由邻居渲染）。
- 跨过任何实心墙线 → 拦截；没跨过 → 放行。再叠加「门洞放行」循环。

线穿越对重叠矩形天然稳健，与渲染完全一致。

## 2. 楼层串台导致穿墙（碰撞静默失效）

**根因**：碰撞是 2D(XZ) 测试，但所有楼层的房间矩形被压平在一起。上下楼层堆叠的房间会污染当前层的墙位置。旧代码用 `round((y-1.6)/storey)` 推算楼层，可能选到一个**没有任何矩形**的楼层索引 → 零矩形匹配 → 所有移动都放行 → 整层墙全可穿。

**修复**：给每个矩形打 `floor` 标签，传入 `storeyH`；用**离脚高最近的楼层基准 Y** 选当前层（而非四舍五入），保证永远落在真实有矩形的楼层上，碰撞不会静默失效。

## 3. 墙看起来「透视」/能看穿到院子

**根因**：近裁剪面被推到 `near=0.3`，顶着墙时墙面落在近平面内被裁掉，于是看穿到外面。

**修复**：`near=0.12`（保留小近裁剪），配合 `useFrame` 里 `WALL_STANDOFF=0.2` 的碰撞间隙——眼睛始终离墙面 ≥0.2m，墙永远在近平面之外，不会被裁。

## 4. 摇杆能走到房子外面

**根因**：每个可行走矩形都向内收 `WALL_HALF`，墙边留出一条窄带，外周墙只有一个房间贴边，外侧半条窄带既不属于任何房间也没有邻居，旧的「双 -1 放行」逻辑就把人放了出去。

**修复**：加「建筑外壳门控」——用整栋 bbox 作为兜底边界，移动若越出外壳则拦截（门除外）。

## 5. 楼梯间外墙透出院子草地

**现象**：外观漫游里，楼梯间那面外墙能看到外面的草地。

**根因**：外墙门洞合成对所有房间用同一个 `pickAutoDoor` 打洞，但**室内渲染只给 `!isStair && !isHallway` 的房间画门板**。结果楼梯间外墙被打了一个「幽灵门洞」，却没有门板填上 → 一个能看穿到院子的缺口。

**修复**（`FloorPlanExterior.tsx`）：合成 auto-door 时排除通行房间——
```ts
const isCircRoom = room === "stair" || room === "hallway";
if (!isCircRoom && configuredDoors.length === 0 && fp.roomHasDoor?.[room] !== false) { ... }
```
与室内渲染口径一致（用户手动配置的门仍生效）。

## 6. 天台看天花板都是透明的

**现象**：站在天台往下看，房间天花板透明，能直接看到下层房间（浴缸、墙面 N/M 标识、地砖）。

**根因**：天花板网格绕 X 轴旋转 -90° 后法线朝上(+Y)，材质用 `side={THREE.BackSide}` 只渲染朝下那一面（下层房间内抬头可见），从天台**往下看时背面被剔除** → 整片天花板透明。

**修复**（`FloorPlanExterior.tsx` 第 ~6952 行）：`THREE.BackSide` → `THREE.DoubleSide`，天花板两面都不透明。这是**通用机制**（天台=普通楼层，不做特判）：普通楼层下层天花板本就被上层楼板挡住、无视觉变化；只在天台这种上方无楼板处让天花板正常遮挡。

> 备注：按既有约定，走廊/楼梯间（通行空间）默认不铺天花板，所以这些位置从天台往下看仍会透。如需也遮挡可另行处理。
